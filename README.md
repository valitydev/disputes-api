# disputes-api

Сервис обработки диспутов по платежам. Принимает обращения с вложениями, отслеживает
их результат и при необходимости запускает корректировку платежа. Возвраты денег
не входят в этот процесс.

## Обработка диспута

1. При создании проверяются наличие платежа, допустимый возраст и параметры обращения.
   Если по платежу уже есть незавершенный диспут, возвращается его идентификатор.
2. Диспут и метаданные вложений сохраняются, дальнейшая обработка выполняется в фоне.
   Пока платеж находится в `pending` или `processed`, обработка ожидает его финализации.
   Уже успешный платеж позволяет завершить диспут без нового обращения к провайдеру.
3. Сервис проверяет результат у провайдера. Если требуется отдельное обращение,
   создает его и опрашивает статус. При необходимости выполняется корректировка платежа.
4. Истечение срока опроса не означает успех или отказ: диспут остается незавершенным.
   Его можно обработать вручную или вернуть к опросу.
5. После завершения результат доступен через API. Если при создании указан адрес
   уведомления, сервис отправляет callback с повторными попытками при ошибках доставки.

API возвращает статусы `pending`, `succeeded` и `failed`. Промежуточные этапы,
включая ручную обработку, ожидание корректировки и истечение опроса, отображаются
как `pending`.

## Корректировки и управление

Корректировки запускаются по результату диспута или обработки уведомления о платеже.
Они могут изменять статус платежа, сумму и данные транзакции. При незавершенном
платеже выполнение откладывается до его финализации.

Создание диспута и чтение результата доступны через HTTP и Thrift. Внутренний
Thrift-интерфейс также позволяет подтверждать и отменять незавершенные диспуты,
обновлять сообщение провайдера, связывать обращения и возобновлять опрос после
истечения срока.

## Данные и фоновые задачи

Состояние обработки, метаданные вложений и задания хранятся в PostgreSQL.
Сами файлы хранятся отдельно. Плановые задачи обрабатывают очереди диспутов,
корректировок и уведомлений; временные ошибки могут переносить следующую попытку
без завершения бизнес-процесса.
